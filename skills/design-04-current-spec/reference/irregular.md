# フェーズ4 の例外のケース

## コードを追っても確定できないセル
「未確認」と書き、確かめる方法(どのコード・どのデータを見ればよいか)を添えて QA.md に起こす。推し量って埋めない。

## コードとドキュメント(`docs/` や `CLAUDE.md`)が食い違う
実装を事実として採る。食い違っている事実を、両方の根拠つきで書き、QA.md に起こす。

## 仕様の根拠が worktree や作業中のブランチにしか無い
まだマージされていない変更なので、既存の仕様としては使わない。「worktree(または `<ブランチ名>`)にマージされていない変更あり」と根拠つきで注記し、既存の仕様の表には入れない。

## 実際のデータで確かめる必要がある
データを書き換える操作(登録・更新・削除のAPI、計算やバッチの実行、マイグレーションなど)は実行しない。各リポジトリの `CLAUDE.md` に、実行してはいけない操作が書いてあれば従う。読み取りの操作とコードを読むことで確かめられない時は「未確認」とする。
