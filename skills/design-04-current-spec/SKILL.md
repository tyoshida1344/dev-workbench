# フェーズ4: 既存の仕様の整理

作業フォルダ(`<作業フォルダ>`)の場所と共通の決まりは `design` スキルにある。

## 手順
1. 「できないこと」「正常系以外の動き」を先に書く
2. 条件ごとの動きを表にする(下の「表の作り方」)
3. 空のセルはコードを追って埋める。**推し量って埋めない**
4. フェーズ3で挙げた似た機能も、**同じ軸・同じ行**の表にして調べる(対象の表と並べて差が分かるように)。類似なしの時は要らない

## 表の作り方
- 1行が、条件の1つの組み合わせ。列は、その条件の時に利用者・運用者から見える結果(画面に出るもの・保存されるもの・送られるもの・エラー)
- 条件の軸は、結果を変える条件だけにする。軸ごとに取りうる値をすべて書き出し、組み合わせが多すぎる時は、結果が同じになる組み合わせをまとめて「その他(…)」の行にし、まとめた理由を書く
- 根拠の列を置き、セルごと(または行ごと)に `repo名:path:line` を書く
- セルには、実際に出る値・文言を書く(「エラーになる」ではなく、出る文言やステータスを書く)
- 埋まらないセルは「未確認」と書く(空のままにしない)

## 表の軸(必ず入れる)
- 既存データの実際にありうる状態を軸に入れる(未登録・複数ある・一意でない・消した、など。design-02 の existing-data.md)
- design-02 で適用すると判定した観点の軸を足す(権限なら ロール × 操作、履歴や有効期間を持つデータなら 有効期間 × 登録した時点 × 過去の結果が変わるか、など)

## 成果物
`<作業フォルダ>/search/NN_<slug>.md`(話題ごとに1ファイル。NN は作った順の連番、欠番は使い直さない。slug は英小文字とハイフン)

## 決まり
- 根拠は、各セルか各行に置く
- 例外(セルが埋まらない・コードとドキュメントが食い違う・worktree にしか無い)→ [reference/irregular.md](reference/irregular.md)。あてはまった時に読む

## 完了条件
- [ ] できないこと・異常系が先頭にある
- [ ] 表に空のセルが無い(埋まらないものは「未確認」)
- [ ] すべてに `repo名:path:line` がある
- [ ] 既存データの実際にありうる状態が軸に入っている
- [ ] フェーズ3の似た機能すべてについて表がある(類似なしを除く)
- [ ] ファイル名が `NN_<slug>.md` の決まりに合っている
