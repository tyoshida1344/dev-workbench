# 既存データへの影響・後方互換

読む時機: どのイシューでも読む(判定せず常に適用する)。design-04 の表の軸と、design-05 の変更後の動きで使う。

## 仕様に必ず書くこと
- 既存データの**実際にありうる状態**を書き出す(未登録・複数ある・一意でない・消した・無効にした・古い形式のまま、など)。コードの制約と、実際のデータの両方から考える
- 状態ごとに、変更の前と後の動き(design-04 / 05 の表の軸に入れる)
- すでに確定したデータや、利用者がすでに受け取った結果(締めたデータ、送った通知、出した帳票など)が変わるか。原則として変えない。変える場合は、変わる条件と範囲を書き、明示的な合意を QA.md に起こす
- 履歴や有効期間を持つデータを扱う時は、過去の時点に登録・変更した場合に、過去の結果が変わるか(変わる・変わらない・条件つき)。変わるなら、どの期間・どの対象か。表の軸に、有効期間・登録した時点・過去の結果が変わるかを加える
- 後方互換: 今の利用者・他のシステム・古い画面(開いたままの画面、キャッシュ)が、変更の後も動くか。API の入出力や保存の形を変えるなら、今の呼び出し元を洗い出す

## してはいけないこと
- 既存データの状態を、コードを読まずに推し量って書く
- データを書き換えて確かめる(読み取りの操作とコードを読むことまで)
