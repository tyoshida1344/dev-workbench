# API と画面の責務の分け方

読む時機: 入力の検証・計算・表示を、API(サーバー)と画面のどちらに置くかが論点になる時。

## 原則
- **今の分け方に揃える**。同じ種類の既存の API・画面で、検証・計算・表示をどちらが持っているかを調べ、揃える先を `repo名:path:line` で示す
- 今の分け方に心配がある時(検証が抜けている・二重になっている・食い違っているなど)は、勝手に変えず、**QA.md に相談として起こす**(書式は design-06-questions)。推奨案は添えるが、仕様には「仮」と書いて載せる

## 仕様に必ず書くこと
- 項目ごとの「検証の置き場」(今に揃える時は、その旨と揃える先)
- エラーの時の応答(ステータス・メッセージを決めるのが、API か画面か)
- リポジトリに API の作り方の決まり(`CLAUDE.md` や `docs/` のガイド)があれば、それに従う

## してはいけないこと
- 今と違う分け方を、相談せずに仕様として確定する
