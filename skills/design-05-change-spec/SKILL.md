# フェーズ5: 変わる仕様の整理

作業フォルダ(`<作業フォルダ>`)の場所と共通の決まりは `design` スキルにある。

## 手順
1. フェーズ4の表と **同じ軸・同じ行** で、変更後の動きを並べる
2. 変わるセルをはっきり示す(変更前 → 変更後)
3. 変わらないセルも残す(変わらないことを確かめた、という意味になる)
4. 既存データの実際にありうる状態ごとに、変更後の動きを書く
5. すでに確定したデータや、利用者がすでに受け取った結果が変わる場合は、変わる条件と範囲をはっきり書く(原則として変えない。変える場合は明示的な合意が要るので、QA.md に起こす)
6. 似た機能(フェーズ4の表)と違う動きにする時は、理由を書き、QA.md に起こす。画面と API の責務は、似た機能の表を揃える先にする
7. 画面がある時は ui.md(design-02 の reference)に従い、今の画面に揃える先、または新しい表示の場所・中身を書く

7 の次に: 書き終えたら、`review-design` スキルで、詰め漏れ・食い違い・書き方の決まりを確かめる。

## 成果物
`<作業フォルダ>/spec/NN_<slug>.md`(話題ごとに1ファイル。NN は作った順の連番、欠番は使い直さない。最終仕様は `<作業フォルダ>/spec.md` に置くので、`spec/` の中には作らない)

## 完了条件

- [ ] 既存データの実際にありうる状態ごとに書いた

- [ ] 仮の記載には、すべて「仮」と書いてある
