# フェーズ1: イシューの中身の確認

作業フォルダ(`<作業フォルダ>`)の場所と共通の決まりは `design` スキルにある。

## 入力
- イシュー番号(どのリポジトリのイシューか分からなければ、[reference/irregular.md](reference/irregular.md))

## 手順
1. `gh issue view <番号> --comments` で本文とコメントを読む(リポジトリは cwd の git remote から。別のリポジトリなら `-R <owner>/<repo>`)
2. リンクされたPR・イシューも読む(PRは `gh pr view <番号> --comments`)
3. 中身を「決まったこと」と「未決」に分ける(書いた人の意見と、合意した事項を混同しない)
4. `<作業フォルダ>/index.md` を作る

## 成果物
`<作業フォルダ>/index.md` に次だけを書く(進み具合・ファイルの一覧・コミットのSHAは書かない)。
- イシューの概要(タイトル・リポジトリ・URL・ラベル)
- リンクされたPR・イシュー
- 決まったこと / 未決(出どころのコメントを示す)

未決は `<作業フォルダ>/QA.md` に起こす(書式は design-06-questions)。

## 決まり
- イシューに書かれた事実だけを書く。自分の解釈はフェーズ2で書く
- 例外(リポジトリが分からない・複数のリポジトリにまたがる・コメントが多い)→ [reference/irregular.md](reference/irregular.md)。あてはまった時に読む

## 完了条件
- [ ] 本文・すべてのコメント・リンク先を読んだ
- [ ] 決まったこと / 未決を分けて書いた
- [ ] `<作業フォルダ>/index.md` がある
- [ ] 推し量って書いたところが無い
