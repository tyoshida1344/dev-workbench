# エビデンスをビューアで見られる形にまとめる

受入確認の動画・画像と、確かめたことを書いた `manifest.json` を1つのフォルダにまとめ、Driveに置いて、
エビデンスビューアのURLを渡すまでを行う。

ビューア: <https://tyoshida1344.github.io/dev-workbench/evidence/?folder=DriveのフォルダID>

## 守ること

- **エビデンスをリポジトリにコミットしない。** 動画・画像・`manifest.json` は、リポジトリの外のフォルダで作る。
  リポジトリに残すのはビューアのURLだけ
- **ファイルの中身を書き換えて見せない。** 撮ったものをそのまま置く。期待どおりでなかった項目(`ng` / `partial`)も消さない
- 確かめたことは、**実際に画面に出た値**を書く。「正しく表示される」ではなく `一覧: ["ひとつめ"]` のように書く

## 手順

### 1. フォルダを作る

リポジトリの外に、1回の確認につき1つ作る。

```
<リポジトリの外>/evidence/2026-11-08-pr22/
```

### 2. 確認する項目を決める

受入条件(PRの本文、Issue、仕様)を読み、**節**と**項目**に分ける。1つの項目は1つの確かめにする。
項目には通し番号(`id`)を振る。

### 3. 撮る

| どんな項目か | 何で撮るか |
|---|---|
| 1つの画面の状態を見れば済む | **画像**(`.png` `.jpg` `.jpeg` `.webp`)。既定はこちら。押してすぐ見られ、軽い |
| 前後の変化や操作の流れを見せる必要がある | **動画**(`.webm` `.mp4` `.mov`) |

- 1つの項目に付けるのは動画か画像のどちらか一方。どちらも無い項目は、ビューアでは押せない行になる
- 撮る手立てはプロジェクトにあるものを使う(Playwright の `video` / `screenshot`、ブラウザの開発ツール、画面収録など)
- ファイル名は `番号-内容.拡張子`。例: `01-add-stays.webm` `02-add-keeps-text.png`
- フォルダは平らにする(サブフォルダを作らない)。`manifest.json` に書くのは**ファイル名だけ**

### 4. manifest.json を書く

[templates/manifest.json](templates/manifest.json) を同じフォルダに写して埋める。形は [reference/manifest.md](reference/manifest.md)。
書いたものがどう出るかは、見本 <https://tyoshida1344.github.io/dev-workbench/evidence/?base=sample/> で見られる。

- `summary` の件数は `result` の数と合わせる
- `checks` の行頭には `○`(期待どおり)/ `△`(一部)/ `×`(期待どおりでない)を付ける
- 文言の中で `` `…` `` で囲んだところは、ビューアで等幅になる(画面の文言やコードに使う)

### 5. 形を確かめる

```
node scripts/check-manifest.mjs <フォルダ>
```

ファイル名の綴り違い、拡張子の間違い、`summary` の数の食い違い、使っていないファイルを見つける。
エラーが出たら直してから次へ進む。

### 6. 手元で見る(dev-workbench を手元に置いている時)

Driveに上げる前に、`?base=` を付けて見ておく(ログインは要らない)。
**ビューアとエビデンスを同じサーバーから配る。** 別の場所(公開しているページなど)から手元のフォルダは読めない。

1. `dev-workbench` とエビデンスのフォルダを、同じ親フォルダの下に並べる

```
<親フォルダ>/
  dev-workbench/      # このリポジトリ
  2026-11-08-pr22/    # 手順1で作ったフォルダ
```

2. 親フォルダを簡易サーバーで配る

```
python -m http.server 8125 --bind 127.0.0.1 --directory <親フォルダ>
```

3. ビューアを開く

```
http://127.0.0.1:8125/dev-workbench/evidence/?base=http://127.0.0.1:8125/2026-11-08-pr22/
```

一覧・印・動画と画像の切り替わりを見て、崩れていないか確かめる。

### 7. Driveに上げて渡す

1. フォルダごとDriveにアップロードする(`manifest.json` も同じフォルダに入れる)
2. 見せる人が読めるように共有する。**読めるのは、その人がDriveで見られるファイルだけ**
3. DriveのURL `https://drive.google.com/drive/folders/<ID>` の `<ID>` を使って、渡すURLを作る

```
https://tyoshida1344.github.io/dev-workbench/evidence/?folder=<ID>
```

4. PRのコメントや報告に、そのURLと1行の要約(件数)を貼る

```
受入確認: 全24項目(✓22 / !2 / ✕0)
https://tyoshida1344.github.io/dev-workbench/evidence/?folder=<ID>
```

## つまずいた時

| 見えたこと | 直し方 |
|---|---|
| 「ログインして開く」のままになる | そのアカウントがフォルダを読めるか、共有設定を見る |
| 項目を押しても何も出ない | `video` / `image` が無い項目。ファイルを足すか、項目を節の説明に回す |
| 「見つかりません」と出る | ファイル名の綴りか大文字小文字の違い。手順5のスクリプトで照合する |
| 動画が止まったまま進む | 連続再生で次へ進むのは動画が終わった時だけ。画像では自動で進まない(仕様) |
