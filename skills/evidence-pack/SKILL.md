# エビデンスをビューアで見られる形にまとめる

受入確認の動画・画像と、確かめたことを書いた `manifest.json` を1つのフォルダにまとめ、Driveに置いて、
エビデンスビューアのURLを渡すまでを行う。

ビューアの場所は [config.json](config.json) の `viewer`。**このスキルを写したら、まず使っているサイトのURLに書き換える。**
以下ではその値を `<ビューア>` と書く(例: `https://example.github.io/dev-workbench/evidence/`)。

## 守ること

- **エビデンスをリポジトリにコミットしない。** 動画・画像・`manifest.json` は、リポジトリの外のフォルダで作る。
  リポジトリに残すのはビューアのURLだけ
- **ファイルの中身を書き換えて見せない。** 撮ったものをそのまま置く。期待どおりでなかった項目(`ng` / `partial`)も消さない
- 確かめたことは、**実際に画面に出た値**を書く。「正しく表示される」ではなく `一覧: ["ひとつめ"]` のように書く
- **受け入れ項目の正本はPRの受入確認。** `manifest.json` の節と項目は、PR本文の受入確認の見出しとチェックボックスを、順番も文言もそのまま写す

## 手順

### 1. フォルダを作る

リポジトリの外に、1回の確認につき1つ作る。

```
<リポジトリの外>/evidence/2026-11-08-pr22/
```

### 2. 受け入れ項目を決める

[reference/cases.md](reference/cases.md) の決まりで項目を作り、PR本文の受入確認に書く。

- 項目は **要件** / **既存機能への影響** / **設計で追加した仕様** の3つの見方に分け、受入確認の見出しもこの3つにする
- 要件(Issue、仕様)、変えた処理を使っている場所、設計で決めたことを書き出し、観点の出どころの表を総なめにして、すべてに項目を付ける
- 1つの項目は1つの操作の結果にし、期待する結果を具体的な値で書く。通し番号(`id`)を振る
- どこから拾ったかと項目の対応を `00-cases.md` に書き、`attachments` に載せる
- cases.md の「撮る前の見直し」を、自分で、続けて別の目で行い、漏れがあれば項目を足してから撮る
- PRの受入確認にすでに項目がある時は、それを正本にして同じ見直しをかけ、足りない項目を受入確認に足す

### 3. 撮る

| どんな項目か | 何で撮るか |
|---|---|
| 1つの画面の状態を見れば済む | **画像**(`.png` `.jpg` `.jpeg` `.webp`)。既定はこちら。押してすぐ見られ、軽い |
| 前後の変化や操作の流れを見せる必要がある | **動画**(`.webm` `.mp4` `.mov`) |
| コマンドで確かめる(lint・テストなど) | 出力のテキスト(`.txt`)。`attachments` に載せる |

- **1項目につき1つ。** 1枚の画像・1本の動画に2つの項目を詰めない(どちらの根拠か分からなくなる)
- 1つの項目に付けるのは動画か画像のどちらか一方。どちらも無い項目は、ビューアでは押せない行になる
- 撮る手立てはプロジェクトにあるものを使う(Playwright の `video` / `screenshot`、ブラウザの開発ツール、画面収録など)。撮り方のこつは [reference/capture.md](reference/capture.md)
- ファイル名は `番号-内容.拡張子`。例: `01-add-stays.webm` `02-add-keeps-text.png`
- フォルダは平らにする(サブフォルダを作らない)。`manifest.json` に書くのは**ファイル名だけ**
- **期待どおりにならなかった項目も撮って残す。** 直してから撮り直した時は、前のものを `番号-内容-修正前.拡張子` として残し、`attachments` に載せる

### 4. manifest.json を書く

[templates/manifest.json](templates/manifest.json) を同じフォルダに写して埋める。形は [reference/manifest.md](reference/manifest.md)。
書いたものがどう出るかは、見本 `<ビューア>?base=sample/` で見られる。

- 節と項目は、PR本文の受入確認の見出しとチェックボックスの**順番どおり**にし、`title` は文言をそのまま写す
- `summary` の件数は `result` の数と合わせる
- 画像の項目は、`checks` が唯一の手がかりになる。**画面のどこを見て○にしたか**まで書く。画像だけでは分からない値(入った文字数、欄の上限など)も書き添える
- `source.commit` は撮った時のコミット。直すたびに一部の項目だけ撮り直したなら、最後のコミットを書き、どの項目をどのコミットで撮ったかを `notes` に書く
- `checks` の行頭には `○`(期待どおり)/ `△`(一部)/ `×`(期待どおりでない)を付ける
- 文言の中で `` `…` `` で囲んだところは、ビューアで等幅になる(画面の文言やコードに使う)

### 5. 形を確かめる

```
node scripts/check-manifest.mjs <フォルダ>
```

ファイル名の綴り違い、拡張子の間違い、`summary` の数の食い違い、使っていないファイルを見つける。
エラーが出たら直してから次へ進む。

### 6. 手元で見る(dev-workbench を手元に置いている時)

Driveに上げる前に、`?base=` を付けて見ておく(ログインは要らない)。
**ビューアとエビデンスを同じサーバーから配る。** 別の場所(公開しているページなど)から手元のフォルダは読めない。

1. `dev-workbench` とエビデンスのフォルダを、同じ親フォルダの下に並べる

```
<親フォルダ>/
  dev-workbench/      # このリポジトリ
  2026-11-08-pr22/    # 手順1で作ったフォルダ
```

2. 親フォルダを簡易サーバーで配る

```
python -m http.server 8125 --bind 127.0.0.1 --directory <親フォルダ>
```

3. ビューアを開く

```
http://127.0.0.1:8125/dev-workbench/evidence/?base=http://127.0.0.1:8125/2026-11-08-pr22/
```

一覧・印・動画と画像の切り替わりを見て、崩れていないか確かめる。

### 7. Driveに上げて渡す

1. フォルダごとDriveにアップロードする(`manifest.json` も同じフォルダに入れる)。上げ方は次のどれか
   - ブラウザでDriveを開いて上げる(手で上げる時、ブラウザを操作できる時)
   - [rclone](https://rclone.org/) の `rclone copy <フォルダ> "<リモート>:<フォルダ名>"`。上げたあと `rclone check <フォルダ> "<リモート>:<フォルダ名>" --one-way` で手元と一致するかを確かめる。Googleへのログインを伴うので、リモートの設定は本人がする
   - DriveのコネクタやAPIでClaudeに上げさせるのは避ける。ファイルの中身を会話に流すので、動画1本で多くのトークンを使う
2. 見せる人が読めるように共有する。**読めるのは、その人がDriveで見られるファイルだけ**
   - 共有は、置き場所の親フォルダの設定に任せる。「リンクを知っている全員」の共有を足さない(`rclone link` もこの共有を足すので使わない)
3. DriveのURL `https://drive.google.com/drive/folders/<ID>` の `<ID>` を使って、渡すURLを作る

```
<ビューア>?folder=<ID>
```

4. PRのコメントや報告に、そのURLと1行の要約(件数)を貼る。`partial` / `ng` があれば、番号とわけを1行ずつ添える

```
受入確認: 全24項目(✓22 / !2 / ✕0)
<ビューア>?folder=<ID>
```

5. PR本文の受入確認のうち、**エビデンスで○(`ok`)だった項目にだけ**チェックを付ける。`partial` / `ng` と、エビデンスを取れていない項目には付けない。
   付ける前に、チェックボックスと `manifest.json` の項目が、順番も文言も一致していることを確かめる

## つまずいた時

| 見えたこと | 直し方 |
|---|---|
| 「ログインして開く」のままになる | そのアカウントがフォルダを読めるか、共有設定を見る |
| 項目を押しても何も出ない | `video` / `image` が無い項目。ファイルを足すか、項目を節の説明に回す |
| 「見つかりません」と出る | ファイル名の綴りか大文字小文字の違い。手順5のスクリプトで照合する |
| 動画が止まったまま進む | 連続再生で次へ進むのは動画が終わった時だけ。画像では自動で進まない(仕様) |
