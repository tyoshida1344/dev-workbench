# 撮り方

画面のエビデンスを撮る時の決まり。撮る手立て(Playwright のスクリプト、Playwright の MCP、ブラウザを操作するツール、画面収録など)によらない撮り方だけを書く。
`test-run` の本体でも、受入確認のまとめ(`test-run/evidence/`)でも、これで撮る。ファイル名と置き場は `test-run/SKILL.md` の「エビデンスを撮る」。

## 画像か動画か

| 確かめ方 | 残すもの |
|---|---|
| 1つの画面の状態を見れば済む(登録した設定・計算した値・データの状態など、準備の証跡も) | **画像**(`.png` `.jpg` `.jpeg` `.webp`)。既定はこちら。押してすぐ見られ、軽い |
| 前後の変化や、操作から結果までの流れを見せないと判らない(条件を選んでダウンロードし中身を見る、申請して承認する、など) | **動画**(`.webm` `.mp4` `.mov`)。画像を並べるだけでは、何をしてその結果になったかが伝わらない |
| コマンドで確かめる(lint・テストなど) | 出力のテキスト(`.txt`)。`attachments` に添える |
| 文書を読んで確かめる | 根拠にした箇所を書いたテキスト。`attachments` に添える |

迷ったら画像にする。1枚で伝わらないと分かってから動画にする。

## 1つの項目に1つ

- **1つの項目に、画像か動画のどちらか1つ**(`manifest.json` の決まり)。期待する結果を確かめた画面を撮る
- **1つのファイルに、別々の操作の結果を詰めない**(どの項目の根拠か分からなくなる)。1つの項目で複数の画面を開く時は、動画で通して撮るか、期待する結果を判定した最後の画面を項目の `image` にし、途中の画面を `attachments` に添える
- ただし、**同じ操作で同じ画面を確かめる項目どうし**は、1つのファイルを複数の項目に書いてよい。同じ中身を別の名前で写さない

## 条件を揃える

- **画面の大きさと倍率を揃える**(例: 1280×720、CSS の大きさ)。揃えないと、ビューアで並べた時に幅が散る。撮り直す時はとくに気をつける
- 使うアカウントは、項目の前提と準備に従う(ログインを Claude が行わないことは `test-run/SKILL.md` の「行えない項目」)

## 項目どうしを切り離す

- 項目の前提が、前の項目の続き(同じ画面・状態のまま)を求める時は、それに従う
- そうでない時は、**1項目を1つのページ(タブ・画面)で撮り、前の項目の状態を持ち越さない**。項目の終わりに、書きかけの入力や開いたままの確認を片付けてから次へ移る。残すと、次の項目の途中で止まったり、前の状態が映り込んだりする

## 撮る時機

- **結果が画面に出てから撮る。** 押した直後に撮ると、変わる前の画面が残る。待つ時は、時間ではなく結果が出たことを待つ。ダイアログの開け閉め・画面の読み込みのあとは、とくに待つ(実例: 開く途中の半透明のダイアログが撮れた)
- **動画は、始まりの画面を開いてから録り始め、結果が出てから少し(1秒ほど)待って止める。** すぐ止めると結果が映らない。画面が切り替わるのを待つ時間は長めにとる(実例: 読み込みの途中で絞り込みを入れて効かず、撮り直した)
- 動画は1本を短くする。上げ方によっては大きさに上限がある
- ログインの間は撮らない(パスワードが映らないよう、ログインを済ませてから始める)

## 動画の印

- 何の確かめかが分かる印を残す。画面の隅に**項目の id と title**、どの値を期待する結果と照らすかを出し、読み終わるまで出しておく
- 印を出す前に、見せたい状態になっているかを確かめる
- 撮ったあとは場面ごとにコマを見て、印・値が写っているかを確かめる

## 画面に映らないものは、値で残す

ブラウザや OS が描くもの(確認のダイアログ、通知、入力の変換候補など)や、画面の外で起きること(通信、保存、ログ)は、画像にも動画にも映らないことがある。
起きたかどうかを、道具から読める値(出来事・戻り値・保存された値)で確かめて `checks` に書く。

## ダウンロードしたファイル

- ファイルそのものを `attachments` に添える(テキストとして開ける形式なら)
- 画面で見せる必要があれば、中身を表にしたページを手元のサーバー(`http://127.0.0.1:<ポート>`)で開いて撮る(`file:` を開けない手立てがある)
- 撮っている間に落としたファイルが、添えたファイルと同じ中身であることを確かめる

## 起こしにくい状態は、本物の仕組みで作る

- 失敗した時の表示は、通信を失敗させる仕組み(通信の差し替えなど)で起こす。サーバーを止めるなど、ほかに影響する手は使わない
- 端末や画面の幅が変わる項目は、端末を指定する仕組みで撮る
- 入力の途中の状態(日本語の変換中など)は、実際の入力の仕組みで作る。**それらしい出来事を送るだけで済ませない**(画面に出ず、エビデンスにならない)。途中の状態が見分けにくい時は、状態を画面の隅に出しておく

## 目で判定するもの

向き・動き・重なりなど、値で判定できないものは、画像や動画のコマを自分で開いて確かめてから○にする。値で判定できた項目も、撮ったものは一度見る(はみ出し・重なりなど、値に出ない崩れを拾う)。
