# 受入確認をまとめる

読む時: `test-run` の振り分けで、テストケースを作っていない PR の受入確認をまとめる・エビデンスを残す時

受け入れ項目を決め、受入確認の動画・画像と、確かめたことを書いた `manifest.json` を作業フォルダの1つのフォルダにまとめ、エビデンスビューアのURLを渡すまでを行う。
流れは **項目を決める → 撮る → まとめる → 渡す → PR に返す**。撮る・記録するは `test-run` の本体と同じ決まりで行う。

- 作業フォルダ・環境変数・Drive への置き方・ビューアのURL: [docs/workspace.md](../../../docs/workspace.md)(`DEV_WORKBENCH_DOCS`・`DEV_WORKBENCH_HOME` が空なら止めて聞く)
- `manifest.json` の欄の意味: [docs/evidence-manifest.md](../../../docs/evidence-manifest.md)

## 守ること

- テストケースを `test-cases` で作ってある時は、この手順ではなく `test-run` の本体で行う(項目の正本がテストケースの `manifest.json` になる)
- **エビデンスをリポジトリにコミットしない。** リポジトリ(PR)に残すのはビューアのURLだけ
- **受け入れ項目の正本は、受け入れ項目の一覧(`00-cases.md` と `manifest.json`)。** PR 本文の受入確認(Test plan)は、それを写したもの。項目を足す・直す時は、一覧を直してから PR に写す
- 撮ったものを書き換えて見せない。期待どおりでなかった項目(`ng` / `partial`)も消さない

## 1. フォルダを作る

1回の確認につき1つ、作業フォルダの `evidence/<YYYY-MM-DD>-<内容>/` を作る(例: `evidence/2026-11-08-pr22/`)。

## 2. 項目を決める

項目は `test-cases/reference/perspectives.md` の決まりで導き、`test-cases/reference/writing.md` の書き方で書く。ゴールは `test-cases/SKILL.md` の「ゴール」の5つ。

- 項目は **要件** / **既存機能への影響** / **設計で追加した仕様** の3つの見方で拾い、`manifest.json` の節もこの3つにする(項目が無い節は作らない)
- 要件(イシュー、仕様)、変えた処理を使っている場所、設計で決めたことを書き出し、観点の出どころの表を総なめにして、すべてに項目を付ける
- 1つの項目は1つの操作の結果にし、期待する結果を具体的な値で書く。通し番号(`id`: `1`、`2`、…)を振る
- どこから拾ったかと項目の対応を `00-cases.md` に書き、フォルダに置いて `attachments` に載せる(形は `test-cases/reference/format.md`「00-cases.md」。「種別」の列には3つの見方を書く)
- PR 本文の受入確認にすでに項目がある時は、それを出どころの1つとして一覧に取り込み、下の見直しをかける
- 仕様から期待する結果が決まらない項目は、推測で埋めない。撮る前に伝えて、決めてもらう

### 撮る前の見直し

**自分で見直す。** 項目を作り終えたら、ゴールに沿って次を1つずつ確かめる。満たしていなければ、項目を足すか直してから撮る。

- [ ] (ゴール1)すべての要件(R1, R2, …)に、その要件を満たしたかを判定できる項目がある
- [ ] (ゴール2)差分のどの行も、どれかの項目に結びついている。観点の出どころの表を総なめにした
- [ ] (ゴール2)変えた処理を使っている場所をすべて探し、影響を受ける場所ごとに項目がある
- [ ] (ゴール2)条件で振る舞いが分かれる変更に、変わらない側の確かめが対になっている
- [ ] (ゴール2)相談して決めたこと、実装中に決めた細かいこと、レビューで足した直しのすべてに項目がある
- [ ] (ゴール3)自動のテストで見ていない動きに、項目がある
- [ ] (ゴール4)すべての項目で、期待する結果が具体的な値になっていて、`checks` に書く値が決まっている
- [ ] (ゴール4)判定できない言葉・コードの名前が残っていない
- [ ] (ゴール5)同じことを確かめる項目が重なっていない。まとめた項目は `00-cases.md` に書いた
- [ ] 確かめないものは、`00-cases.md` と `notes` に「確かめないこと」としてわけを書いた

**別の目で見直す。** 書いた本人の見直しだけでは、同じ思い込みで漏れる。サブエージェントなど**書き手とは別の文脈**に、項目の一覧・差分・イシューだけを渡し(書いた途中の考えは渡さない)、漏れを探してもらう。

- 見てもらうもの: 上の「自分で見直す」の各項目と、ゴールの5つ。ゴールごとに「満たしている/満たしていない」と根拠を返してもらう
- 返してもらう形は `review/SKILL.md` の出力の形。重要度のこのレビューでの意味は次のとおり。直すのは書き手

| 重要度 | このレビューでの意味 |
|---|---|
| P1 | 漏れ。項目を足さないといけない(どの項目でも通らない分岐、判定できない要件、影響先の抜け) |
| P2 | 中身の誤り。期待する結果・前提が違っていて、判定できない、または誤って○になる |
| P3 | 書き方の揺れなど |

- 項目を増やす指摘は、要件が判定できない・誤って○になる、といった重いものに限ってもらう(むやみに増やさない)
- 調べて問題が無かったところも一言ずつ返してもらう(調べていないところを「問題なし」としない)
- P1・P2 を直す。P1 があった時だけ、もう一度見てもらう(2回まで)。2回目でも P1 が残るなら、ユーザーに判断を仰ぐ

## 3. 撮る

`test-run/SKILL.md` の「エビデンスを撮る」(ファイル名・置き場)と `test-run/reference/capture.md`(撮り方)に従う。撮る手立ては、プロジェクトにあるものを使う。

- 項目に無い操作は撮らない。撮っている途中で足りないと気づいたら、先に一覧に項目を足してから撮る
- 直してから撮り直す時は、前のものを残す(`test-run/retest/` の「同じ回の中での撮り直し」)

## 4. まとめる

[templates/manifest.json](templates/manifest.json) をフォルダに写して埋める。結果・`checks`・`summary`・`notes` の書き方は `test-run/SKILL.md` の「記録する」。

- 節と項目は、項目の一覧(`00-cases.md`)の順にし、`title` は項目の確認内容にする
- `source.commit` は撮った時のコミット。直すたびに一部の項目だけ撮り直したなら、最後のコミットを書き、どの項目をどのコミットで撮ったかを `notes` に書く
- 確かめられなかった項目も消さずに `partial` にし、`note` にわけを書く
- 書いたら `check-manifest.mjs <フォルダ>` で確かめ、エラーが出たら直してから次へ進む(コマンドは `test-cases/reference/format.md`「正本と証跡を作る」)

## 5. 渡す

1. 同期で Drive に上がったことを確かめ、フォルダの ID からビューアのURL(`<site>evidence/?folder=<ID>`)を作る(作り方は [docs/workspace.md](../../../docs/workspace.md) の「Driveへの置き方」「ビューアで開く」)
2. そのURLで開き、一覧・印・動画と画像の切り替わりが崩れていないかを見る
3. 報告に、URLと1行の要約(件数)を書く。`partial` / `ng` があれば、番号とわけを1行ずつ添える

```
受入確認: 全24項目(✓22 / !2 / ✕0)
<site>evidence/?folder=<ID>
```

## 6. PR に返す(PR があれば)

PR がまだ無ければ、PR を作る時に、ここで決めた項目の一覧とURLを使う(PR を作る手順の側で行う)。

1. PR 本文の受入確認(Test plan)に、項目の一覧を写す。見出しは3つの見方、1つのチェックボックスが1つの項目で、**順番も文言も一覧(`manifest.json` の節と項目)のとおり**にする
2. PR のコメントに、上の「渡す」のURLと要約を貼る
3. 受入確認のうち、**エビデンスで○(`ok`)だった項目にだけ**チェックを付ける。`partial` / `ng` と、エビデンスを取れていない項目には付けない。付ける前に、チェックボックスと `manifest.json` の項目が、順番も文言も一致していることを確かめる

## つまずいた時

| 見えたこと | 直し方 |
|---|---|
| 「ログインして開く」のままになる | そのアカウントがフォルダを読めるか、共有設定を見る |
| 項目を押しても何も出ない | `video` / `image` が無い項目。ファイルを足すか、項目を節の説明に回す |
| 「見つかりません」と出る | ファイル名の綴りか大文字小文字の違い。`check-manifest.mjs` で照合する |
| 動画が止まったまま進む | 連続再生で次へ進むのは動画が終わった時だけ。画像では自動で進まない(仕様) |
