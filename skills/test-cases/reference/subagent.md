# サブエージェントの約束

テストケースのサブエージェント(`test-cases/agents/` の5つ)に共通の約束。サブエージェントは親の会話を見られないので、ここと、各サブエージェントのファイルの「先に読む」に挙げたものだけが決まりになる。

## 動く条件

- パスは、親が渡す絶対パス(作業フォルダ・対象のリポジトリ・`$DEV_WORKBENCH_HOME`)で読む。環境変数は読めないことがある。手順やファイルの場所は `$DEV_WORKBENCH_HOME/skills/` からの場所で書いてある(`test-cases/reference/format.md` など)
- コマンドの実行は、`test-cases/SKILL.md` の「一番大事な決まり」に従う(項目に書くコマンド・状態を変えるコマンドは実行しない。本番の環境には、親がユーザーの指示として渡した時だけ、読み取りでつなぐ)。Bash を持つ担当も、使うのは `git diff` / `git log` / `git show` / `grep` / `gh ... view` / `check-cases.mjs` など読み取りだけのコマンドに限る。外のサービスの読み取りだけの GET(状態を変えない。実際のコードの名前の実測など)は、API のキーを出力・ファイルに書かないことを条件に使ってよい
- `check-cases.mjs` は、権限の設定で実行できないことがある。実行できなければ、終わりの報告に「未実行」と書く(実行できたふりをしない。親が必ず実行する)。1つのファイルだけを確かめる時は、`--file` にファイルの名前ではなく**パス**を渡す(形は `test-cases/reference/format.md`「正本と証跡を作る」)
- コードや差分を読む時は、親が渡した作業ツリーとコミットの範囲を使う(`git -C <作業ツリー> diff <範囲>`)。手元のチェックアウトが別のブランチのことがある
- PR の本文やイシューのコメント、作業フォルダの設計などの外の文書は、親がプロンプトに貼ったものを使う(自分で取れないことがある)
- 事実(実際のデータの名前、画面の言葉、権限の名前)は、親が渡した事実のシートと、決まった `setup.json` に従う。シートに無い値は推測で書かず、`【要確認】` にして報告で返す

## 項目を書く担当の約束(単体・結合・回帰・受け入れ)

- 書き込むのは、親が渡した書き込む先の1つのファイル(`<作業フォルダ>/cases/<kind>.json`)だけ。`plan.json`・ほかの種別のファイル・対象のリポジトリは触らない(フックでは止めないので、各自が守る)。結合・受け入れは、作業フォルダと `$DEV_WORKBENCH_HOME` の決まりの外のコードを読まない
- 出力は `{ "sections": [...] }` だけを持つ JSON。各節に自分の種別の `kind` を付ける。渡された節の中身(`notes` と `items`)だけを書き、節を増やしたり減らしたりしない。項目の `id` は渡された節の `id` を頭にする(`tc02-01`)
- `duplicateOf` は付けない(種別をまたぐ重なりは、親が付ける)
- 分からないことは推測で埋めず、該当の欄に `【要確認】<質問>` と書く([writing.md](writing.md)「分からないことは聞く」)
- 書き終えたら、[writing.md](writing.md) の「読みやすく書く」の11の決まりで見直す

## 終わりの報告

書いた節と項目の数、`check-cases.mjs` の結果(または「未実行」)、`【要確認】` の質問の一覧(項目の id ごと)、親に確かめてほしいこと。
レビューの担当は、`test-cases/review/` の出力の形で返す。
