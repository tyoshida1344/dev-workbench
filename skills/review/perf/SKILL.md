# 性能とコード量のレビュー

読む時: `review` の振り分けで、処理・データの取り方・繰り返しを変えた時

変更の差分を「コード量を減らせないか」「処理を軽くできないか」「共通にできないか」で確かめる。
共通の進め方(比べる先・対象の特定・見る範囲・重要度・出力の形・直すかどうか)と、ほかの観点との境界は `review/SKILL.md`。

## 対象の特定

`review/SKILL.md` の「対象の特定」に加えて、プロジェクトの共通の部品・ユーティリティ・CSS の変数・定数がどこにあるかを、CLAUDE.md と既存のコードから探しておく(置き換えられる既存のものを見落とさないため)。

## 確認観点

全部を機械的に確かめるのではなく、**実際に効く指摘**に絞る。

### コード量の削減

- 要らない変数・関数・条件分岐・引数・コメントアウトしたコードが無いか
- 同じ計算を何度も呼んでいないか(変数に入れて使い回せないか)
- 言語・フレームワークの機能(標準のメソッド、型のユーティリティ、テンプレートの繰り返しなど)で短く書ける所が無いか
- 直書きした値を、決めてある所(定数・パス・文言・設定・CSS の変数・デザインのトークン)から引けないか

### 共通処理の再利用・切り出し

- **既存の部品で置き換えられる独自の実装**が無いか(プロジェクトのユーティリティ・共通のコンポーネント・ヘルパー)
- 同じ形の処理が2か所以上に出ていないか。**2か所目を書く時が分ける時**(揃えて直すだけだと、また離れる)
- 逆に、1か所でしか使わないのに切り出して、読む場所が増えただけになっていないか
- 切り出す先の層が合っているか(依存の向き)は → 実装のレビュー(`review/impl/`) の「作り」で見る

### 処理の軽量化

- ループの中の変わらない計算を外に出せないか。同じデータを何度も走査していないか
- 頻繁に起きるイベント(入力・スクロール・リサイズ)で重い処理が走っていないか(間引き・遅らせる・必要な時だけ)
- 画面の不要な描き直し・再計算が無いか(フレームワークのメモ化・算出プロパティ・表示の切り替え方の使い分け)
- 要らないリアクティブ・状態を持っていないか(変わらないデータは素の値で足りる)

### データの取り方

- **同じものを取り直していないか**(画面を切り替えるたびに同じ取得が走る、など。キーを揃えて1回にする)
- **件数ぶん問い合わせていないか**(一覧の行ごとに問い合わせない。数えるものは一緒に返す)
- **件数が増えた時に耐えるか**(全件を返す・全件を描く前提でよいか。上限の無いものはどこまで伸びるか)
- 大きなファイル・画像・ライブラリを、要らない所で読み込んでいないか

### 測ったか

- 「速くなったはず」で指摘・修正しない。**リクエストの数・時間・描く回数を実際に数える**。測れない時は「推測」と書く

## 出力

観点の見出しは、コード量の削減 / 共通処理の再利用・切り出し / 処理の軽量化 / データの取り方 の順。
共通化の指摘には、置き換える既存の部品か、切り出す先を添える。軽くする指摘には、測った数(測れない時は「推測」)を添える。
