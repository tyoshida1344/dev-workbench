# 使い勝手のレビュー

読む時: `review` の振り分けで、画面・文言・操作を変えた時

変更が利用者にとって使いやすいかを、利用者に見える形と言葉で確かめ、改善点を指摘する。
共通の進め方(比べる先・対象の特定・見る範囲・重要度・出力の形・直すかどうか)と、ほかの観点との境界は `review/SKILL.md`。
設計では `design/reference/viewpoints/ui.md` で決めたこと。

## 対象の特定

`review/SKILL.md` の「対象の特定」に加えて、次を行う。

1. 関連する部品・CSS・文言を読み、画面での見え方・動き方をつかむ。**動かせる時は、実際に画面を開いて見る**(プロジェクトにある手立て: 開発用のサーバー・ブラウザの操作・スクリーンショット)
2. プロジェクトのデザインの方針(README・`docs/` のデザインの節・CSS の変数・共通の部品)を探して読む。観点の例より、プロジェクトの方針を優先する

## 確認観点

### 操作の手応え

- 押した・送った後に、結果が目で分かるか(知らせ・状態の変化・強調)
- 時間がかかる処理で、何が起きているかが分かるか(読み込み中の表示)。押せないまま固まらないか
- 成功と失敗がはっきり見分けられるか
- 押せる所が押せると分かるか(カーソル・色・下線・ホバー・押した時の状態)
- 次に何をすればよいかが画面から分かるか。**何も無い状態に、案内と操作**があるか

### エラーの扱い

失敗を伝える言葉と、やり直せるかを見る。失敗を握りつぶさない仕組みは → 実装のレビュー(`review/impl/`) の「正しさ」で見る。

- 不正な入力(空・0・負の数・形の違う値・極端に大きい値・長すぎる文字)に、分かる言葉で応えるか
- エラーの文言が、何が悪くて、どうすればよいかを伝えるか(内部のコード・英語のまま・受け取った値をそのまま出していないか)
- 失敗しても、**やり直せる状態に戻るか**(入力を消さない、押せないまま固まらない)
- 取り消せない操作(削除・送信)に、確かめ・取り消しの手段があるか

### キーボードの操作

- Tab で、見た目の並びどおりにすべての操作の所へ移れるか。フォーカスが見えるか
- Enter・Esc など、期待するキーで決定・閉じるができるか。窓を閉じた後、フォーカスが元へ戻るか
- 数値・メールなどの入力に、合った入力の種類(`inputmode`・`type`)が付いているか(携帯で合ったキーボードが出るか)
- キー操作を足した・変えたなら、ヘルプや案内に載っているか

### 見た目のそろい

| 原則 | 見ること |
|---|---|
| **近接** | 関係のあるものは近づけ、無いものは離す。まとまりは余白で作る(線を足して分けない) |
| **整列** | 端を揃える。揃え方を画面の中で散らさない。数字は桁を揃える |
| **反復** | 同じ役割のものは同じ見た目にする。**変えた画面の中だけでなく、ほかの画面の同じ役割のもの**(取り消しのボタン、作成のボタン、空の時の案内など)と見比べる。間隔・色・文字の大きさが1か所だけ違っていないか(決めてある値から引いているかは → 性能とコード量のレビュー(`review/perf/`) の「コード量の削減」で見る) |
| **対比** | 違うものははっきり違える。強調は1画面に1つに絞る |

- 出すものを減らせないか。説明を足して分かるようにするのではなく、**説明が要らない形**にする

### 狭い幅での表示

- 携帯の幅(375px など)で、はみ出し・重なり・切れが無いか
- 押す所が指で押せる大きさか(44×44px が目安)
- 表・長い文字・数値が、狭い幅でも読めるか(折り返し・横のスクロール)

### アクセシビリティ

- 入力に、見出し(`label`)が結び付いているか
- アイコンだけのボタンに、読み上げの名前があるか。画像に代わりの文があるか
- **色だけで伝えていないか**(記号や文字を添える)。文字と背景のコントラストが足りるか
- 明るい・暗い表示の両方で読めるか(切り替えがあるプロジェクトの時)

### 画面の文言

見出し・ボタン・案内だけでなく、読み上げの名前・`placeholder`・確かめの窓・失敗の文言・ヘルプの文も、1つずつ読む。

- 設計や開発の中だけの呼び方が、利用者に出ていないか
- 普段使う短い言葉か。説明の言い回しより、名詞1つで通じる言葉。ボタンは動詞でもよいが、文にしない
- 同じものを同じ言葉で呼んでいるか(見出しと中身、ほかの画面の同じ役割の文言)
- `placeholder` や案内に、操作の説明を詰め込んでいないか
- 決まっている表示(注意書き・免責・個人情報の扱いなど)が、消えたり隠れたりしていないか

足した・変えた文言は一覧にして見せる。気になるものには案を添え、言い換えは決めずに選んでもらう。

## 出力

観点の見出しは、操作の手応え / エラーの扱い / キーボードの操作 / 見た目のそろい / 狭い幅での表示 / アクセシビリティ / 画面の文言 の順。
文言の指摘は `` `今の文言` → 案: `…` / `…` `` の形で、案を複数並べる。見た範囲には、実際に開いた画面と幅を書く。
