# フェーズ7: 最終仕様のまとめ

作業フォルダ(`<作業フォルダ>`)の場所と共通の決まりは [SKILL.md](/.claude/skills/design/SKILL.md)にある。

## 成果物
`<作業フォルダ>/spec.md`(最終仕様)。実装の方針・計画(`impl.md`)は、フェーズ9で作る

## 手順
1. ひな形 [templates/spec.md](/.claude/skills/design/templates/spec.md) を写し、変更仕様(`spec/`)と `search/` の中身を、ひな形の `> 書き方:` に従って節ごとに埋める。詳細仕様の小節は、ひな形の「話題の候補」から、変更に関係するものを選ぶ
2. QA.md に残っている項目は、該当する行に「仮」と書いて載せる
3. 詰め漏れの観点([viewpoints/completeness.md](/.claude/skills/design/reference/viewpoints/completeness.md))で確かめる

## 決まり
- 最終仕様をイシューへコメントとして載せる時は、載せる前にユーザーに確かめる。載せる文面はユーザーに見せる
- `issue-handler` から来た時は、どのフェーズまで行うか・イシューへのコメントは `issue-handler/SKILL.md` に従う
- 例外(仮確定が残ったまま進める必要がある、など)→ 末尾の「例外のケース」。あてはまった時に読む

## 完了条件
- [ ] 確定と仮の区別がつく(仮には「仮」と書いてある)
- [ ] 仮が QA.md の未決と一致している
- [ ] 本文にコードの識別子・実装の方法・`path:line` が書かれていない
- [ ] 未確認のことが `spec.md` に混じっていない(QA.md に起こしてある)
- [ ] 設計のレビュー(`design/review/`) で確かめた。見る・触るものの名前・置き場所・権限・既定値・リリース直後の状態が書いてある
- [ ] search/・spec/ の中身と矛盾が無い
- [ ] ひな形の説明(`> 書き方:`)が残っていない
- [ ] 仮が無ければ、QA.md が無い(または空)。ほかの成果物・QA.md を参照していない

## 例外のケース

### 仮確定が残ったまま実装を進めたい
決めるのは人。実装の側には「仮確定の範囲」と「その仮が外れた時に、やり直しになる範囲」を `spec.md` に書いて渡す。仮確定を、確定として書き換えない。

### 回答で、フェーズ4・5の前提が崩れた
`spec.md` を書く前に、前提が崩れた search/・spec/ のファイルを直し、そのフェーズの完了条件を満たし直す。
