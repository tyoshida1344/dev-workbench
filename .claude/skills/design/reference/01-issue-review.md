# フェーズ1: イシューの中身の確認

作業フォルダ(`<作業フォルダ>`)の場所と共通の決まりは [SKILL.md](/.claude/skills/design/SKILL.md)にある。

## 入力
- イシュー番号(どのリポジトリのイシューか分からなければ、末尾の「例外のケース」)

## 手順
1. `gh issue view <番号> --comments` で本文とコメントを読む(リポジトリは cwd の git remote から。別のリポジトリなら `-R <owner>/<repo>`)
2. リンクされたPR・イシューも読む(PRは `gh pr view <番号> --comments`)
3. 中身を「決まったこと」と「未決」に分ける(書いた人の意見と、合意した事項を混同しない)
4. `<作業フォルダ>/index.md` を作る

## 成果物
`<作業フォルダ>/index.md` に次だけを書く(進み具合・ファイルの一覧・コミットのSHAは書かない)。
- イシューの概要(タイトル・リポジトリ・URL・ラベル)
- リンクされたPR・イシュー
- 決まったこと / 未決(出どころのコメントを示す)

未決は `<作業フォルダ>/QA.md` に起こす(書式は フェーズ6([06-questions.md](/.claude/skills/design/reference/06-questions.md)))。

## 決まり
- イシューに書かれた事実だけを書く。自分の解釈はフェーズ2で書く
- 例外(リポジトリが分からない・複数のリポジトリにまたがる・コメントが多い)→ 末尾の「例外のケース」。あてはまった時に読む

## 完了条件
- [ ] 本文・すべてのコメント・リンク先を読んだ
- [ ] 決まったこと / 未決を分けて書いた
- [ ] `<作業フォルダ>/index.md` がある
- [ ] 推し量って書いたところが無い

## 例外のケース

次のどれかにあてはまったら、自分で判断せず、**その都度ユーザーに聞く**。

- リポジトリが分からない(cwd の git remote から決められない、または cwd とは別のリポジトリのイシューかもしれない)
- 複数のリポジトリに関連するイシューがあり、どれを主にするか決められない
- コメントが多く、方針が途中で変わっていて、どれが最新の合意か判断できない

質問には、確かめた事実(どのイシュー・どのコメントか)と、考えられる選択肢を添える。
