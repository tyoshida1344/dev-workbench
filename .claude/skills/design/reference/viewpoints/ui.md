# UI

読む時機: 画面を足す、または表示を変える時。

## 調べて書くこと(根拠は search/、決めたことは spec.md)
- 新しい表示を作る前に、同じ種類の既存の画面・部品(コンポーネント)を、画面のコードから探す。揃える先は `repo名:path:line` で `search/` に残し、`spec.md` には揃える先の画面・部品の名前を書く
- 揃えられない時は理由を書き、QA.md に起こす

## まったく新しい表示の時
次を仕様で詰めてから確定する。
- どの画面のどこに出すか
- 何を表示するか(項目・並び・書式)
- 表示する条件(権限・データの状態)

## 画面の状態
- 正常系以外(空・エラー・読み込み中・権限なし)の表示を必ず書き出す
- 画面の変更が大きい時は、画面イメージを作る(置き方は [SKILL.md](/.claude/skills/design/SKILL.md) の共通の決まり)

実装では、使い勝手のレビュー(`review/ux/`)で確かめる。
