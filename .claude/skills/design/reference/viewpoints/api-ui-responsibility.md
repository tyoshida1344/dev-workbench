# API と画面の責務の分け方

読む時機: 入力の検証・計算・表示を、API(サーバー)と画面のどちらに置くかが論点になる時。

## 原則
- **今の分け方に揃える**。同じ種類の既存の API・画面で、検証・計算・表示をどちらが持っているかを調べる
- 今の分け方に心配がある時(検証が抜けている・二重になっている・食い違っているなど)は、勝手に変えず、**QA.md に相談として起こす**(書式は フェーズ6([06-questions.md](/.claude/skills/design/reference/06-questions.md)))。推奨案は添えるが、仕様には「仮」と書いて載せる
- リポジトリに API の作り方の決まり(`CLAUDE.md` や `docs/` のガイド)があれば、それに従う

## 調べて書くこと(根拠は search/、決めたことは spec.md)
- 揃える先: 既存の API・画面を `repo名:path:line` で `search/` に残す。`spec.md` には、今に揃えることと、揃える先の名前を書く
- 項目ごとの「検証の置き場」(API か画面か)
- エラーの時の応答(ステータス・メッセージを決めるのが、API か画面か)

## してはいけないこと
- 今と違う分け方を、相談せずに仕様として確定する
