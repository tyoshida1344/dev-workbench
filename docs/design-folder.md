# 設計の Markdown

設計のビューア(`app/design/`)が読む、作業フォルダ([workspace.md](./workspace.md))の Markdown の決まり。
書き上がりがどう出るかは、見本([`sample/design/`](../sample/design/))で見られる。ビューアを `?folder=sample` で開く。

## 一覧に出る順

作業フォルダの直下の決まったファイルを、設計を進める順に呼び名で出す。その後ろに、下書きのフォルダを1段ずつ出す。

| ファイル | 呼び名 |
|---|---|
| `index.md` | 概要 |
| `QA.md` | 未決 |
| `spec.md` | 最終仕様 |
| `acceptance.md` | 受け入れ基準 |
| `impl.md` | 実装の方針・計画 |
| `test.md` | テストの方針・計画 |

| フォルダ | 呼び名 |
|---|---|
| `search/` | 調査 |
| `spec/` | 変更仕様 |
| `impl/` | 実装の下書き |
| `test/` | テストの下書き |

- 決まったもの以外の `.md` は、直下なら決まったファイルの後ろに、フォルダの中ならそのフォルダの下に、ファイル名の順で出す。呼び名は最初の `#` 見出し
- `evidence/` の下のフォルダは「テスト・エビデンス」として出し、押すとエビデンスビューアで開く
- 見本(`?folder=sample`)はURLから読むので、フォルダの中身を一覧できない。文書は決まったファイルから相対リンクをたどって集め、「テスト・エビデンス」にはエビデンスビューアの見本を出す
- `images/` と `cases/` は一覧に出さない

## 書ける記法

見出し(`#`〜`####`)・段落・箇条書き(入れ子も)・番号付き・表・コードブロック・引用・水平線と、行内の `**強調**`・`*斜体*`・`` `コード` ``・リンク・画像。

- **HTMLは書けない。** 書いても文字としてそのまま出る(読み込んだ文字は `textContent` で出すため)
- ほかの `.md` へのリンクは相対パスで書く(`[最終仕様](spec.md)`、`[調査](../search/01_requirements.md)`)。ビューアの中で開く
- 画像は相対パスで書く(`![一覧の画面](images/list.svg)`)。`.png` `.jpg` `.jpeg` `.webp` `.gif` `.svg` を出せる。`https://` の外の画像は読み込まず、リンクとして出す(開いた人の情報を外のサーバーに送らないため)
- リンクは `https://` と相対パスだけを開く(`javascript:` などは開かない)
